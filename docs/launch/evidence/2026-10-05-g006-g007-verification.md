## Defects fixed by this candidate

1. **JWT-expiry logout retry loop** (G-007): `isAuthEndpoint` guard + single logout — live-verified.
2. **Broken silent refresh**: refresh required a store token that never exists; now cookie-based (`credentials:'include'`, backend contract `{accessToken}`) — live-verified.
3. **Photo upload 404**: frontend posted `/api/uploads/photo` (nonexistent) and read `res.data.data.url`; now `/api/upload` + `{url}`, with a visible failure message instead of silent skip.
4. **Questionnaire never loaded / photos unmapped**: seeded preset had `version:"1.0"`, no `sections`, no `order` (violates `isServiceQuestionnaireV1`) → `/schema` 500 → submit fell back to a schema with 0 photo fields → 400 "fieldId is required". Preset normalized to V1 (+ one `project_photos` field); frontend parses `schema.fields`, renders select/boolean/date/textarea, and maps/drops photos per contract (`resolvePhotoFieldId`/`applyPhotoFieldMapping`).
5. **"Invalid Date" in admin Recent Activity**: `/admin/audit-log` leaked raw rows (`timestamp`) while the UI reads `createdAt` — mapped via `lib/adminAudit.ts` (`toAuditLogEntry`), 4 unit tests.
6. **Hardcoded credential fallback** in `lib/mediaDb.ts` removed (requires `MEDIA_DATABASE_URL`).
